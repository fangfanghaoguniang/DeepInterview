## 1. 总体架构

### 1.1 Monorepo 布局（pnpm workspace + turbo）

```
apps/web        Next.js（App Router）前端 + 服务端 BFF
apps/agent      Python（uv）：FastAPI + LangGraph 管线 + 两个 LiveKit worker
packages/shared 跨语言数据合同（TS Zod 唯一真相 → 生成 JSON Schema）
packages/ee     企业版占位
cli/            TypeScript CLI（部署编排，需 shared/cli 先建 dist）
services/lightrag  可选知识库 sidecar（Python）
supabase/migrations  Postgres 演进（0001-0008）
skills/         32 个角色面试画像（Markdown）
```

### 1.2 进程拓扑与端口

| 进程 | 端口 | 说明 |
|---|---|---|
| next dev / 站点 | 3000 | 页面渲染 + BFF（持秘密、签 LiveKit 令牌、代发写请求） |
| Agent API（uvicorn） | 8000 | 唯一读写持久层的 FastAPI；`pnpm dev` **不会**带起它，需手动起 |
| interview worker | — | `python -m deepinterview_agent.worker start`，LiveKit job 进程 |
| coach worker | — | `python -m deepinterview_agent.worker_coach start`，独立分派名 `deepinterview-coach`，与面试 job 物理隔离 |
| lightrag sidecar | 9621 | 可选 |

**关键结构约束**：worker 与 API 是两个进程。未配 Supabase 时二者各持独立内存字典，互不可见，因此所有"UI 需要读到"的写路径必须经 HTTP 传话：面试结果走 `POST /api/session/{id}/live-result`，教练自评走 `POST /api/coach/progress`。配置 Supabase 后两进程共享同表，HTTP 写回仍兼容（幂等覆盖）。

### 1.3 数据流总览

```
prep:      表单 → POST /api/prep → LangGraph(简历抽取→选skill→出题→校验) → InterviewContext 落库
live:      面试页(SSE 验会话→签令牌) ⇄ LiveKit 房间 ⇄ worker(InterviewerAgent, save_answer 工具)
             └ 关闭: reconstruct_answers → POST live-result → 触发评分
post:      /api/score 或 live-result 内联 → 逐能力打分 + LLM 报告(含 growth_items) → ScoreCard 落库
coach:     prep 页 → POST /api/coach/plan(growth_items→模块, practice_state 覆盖)
             卡面: 真题+范文 (+溢出模块 POST /api/coach/drill → drill_items)
             语音: /interview/coach?session= → coach worker(CoachAgent, wrap_up 自评)
             关闭: POST /api/coach/progress → practice_state
```

## 2. 跨语言数据合同层

### 2.1 单一真相与生成链

- TS 源：`packages/shared/src/*.ts`（Zod）。`registry.ts` 汇总 **恰好 32 个**注册 schema；`pnpm --filter @deepinterview/shared gen:schema` 把它们导出为 `packages/shared/schema/*.json`。
- Python 镜像：`apps/agent/src/deepinterview_agent/shared_models.py`（Pydantic，`extra="forbid"`）。
- 双向钉死：`packages/shared/src/roundtrip.test.ts`（TS 侧 6 例）与 `apps/agent/tests/test_parity.py`（33 例：逐注册模型比对字段形状）互斥漂移。**改 Zod 字段后必须重跑 gen:schema，否则 parity 红**（本轮改 ScoreCard 时实际触发并修复过）。
- 子对象纪律：`GrowthItem`、`DrillItem` 等被引用但**不注册进 MODELS**（内联进父 schema），否则 32 项断言变红。

### 2.2 本轮合同变更

```ts
// packages/shared/src/score.ts
export const GrowthItemSchema = z.object({
  text: z.string(),        // 报告散文（跟随面试语言）
  competency: z.string(),  // 必须取自本次评分能力项
});
// ScoreCardSchema 增: growth_items: z.array(GrowthItemSchema).default([])
```

```python
# shared_models.py（镜像）
class GrowthItem(BaseModel): ...            # 不入 MODELS
class ScoreCard(BaseModel):
    growth_items: list[GrowthItem] = Field(default_factory=list)

PracticeState = dict[str, MasteryState]      # 类型别名，不注册
class DrillItem(BaseModel):                  # 不入 MODELS
    id: str; competency: str
    text: LocalizedText; answer: str
```

两套独立词表：`MasteryLevel = weak|developing|solid|strong`（面试档位）与 `MasteryState = unseen|learning|shaky|mastered`（练习状态）。换算：`_status_for_level`：`developing→"learning"`，其余弱档→`"shaky"`。

## 3. 持久化层

### 3.1 三实现结构

`core/persistence/repository.py`：`SessionRepository` Protocol + `MemoryRepository`（进程字典，默认）+ `SupabaseRepository`（Postgres）。选择逻辑：`SUPABASE_URL` 与 `SUPABASE_SERVICE_ROLE_KEY` 齐备才走库，否则内存（半配启动期大声告警）。

### 3.2 sessions 表形态（每场面试一行）

`id, status, progress, prep_warnings, context(jsonb), scorecard(jsonb), coach_transcript(jsonb 0004), practice_state(jsonb 0007, default '{}'), drill_items(jsonb 0008, default '[]')`，另加行级安全与 profiles。

**窄读面哲学**：`SessionView`（`GET /api/session/{id}`）的 select 列串被测试钉死为 `id,status,progress,prep_warnings,context,scorecard`；`coach_transcript/practice_state/drill_items` 刻意**不进** SessionView，各配专用读写方法，避免大 JSON 顺带外泄与视图合同膨胀。

### 3.3 本轮新增方法（三实现同步）

| 方法 | 语义 |
|---|---|
| `get_practice_state(sid)` | `None`=查无此会话；`{}`=存在但未练（两语义分离，沿用 coach_transcript 约定） |
| `set_practice_state(sid, comp, state)` | read-modify-write 单键（仿 `mark_progress`），值相同不写库 |
| `get_drill_items(sid)` | `None`=查无此会话；`[]`=未生成 |
| `add_drill_items(sid, items)` | 按 `id` upsert，有变化才写，返回全量 |

内存实现同构语义，保证测试与降级行为一致。`_SessionRow` 相应加 `practice_state: dict` / `drill_items: list` 字段。

## 5. 四阶段改造详细设计

### 5.1 阶段 1 — growth_items 单一真相源（R1）

**生成链**：`post/prompts.py report_summary_prompts` 要求 LLM 除散文外输出 `growth_items:[{text, competency}]` → `post/report.py _ReportNarrative` 承接 → `generate_report` 透传进 `ScoreCard.growth_items`。

**消费链（三处同源）**：

1. `coach/__init__.run_coach_plan`：
   - `items = [(gi.competency, gi.text) for gi in scorecard.growth_items]`，空则回退 `weak_competencies`；两者皆空返回 `_empty_plan`。
   - **形态 Y**：不做分数线过滤；模块上限截断时按 `{cs.competency: cs.score}` 升序排序，**不在评分表里的条目按 99.0 排最后**（溢出维度语义优先，仅溢出时才可能被动截尾）。
   - 每模块 `evidence` 取成长条目散文（即报告原文），实现"报告说什么，计划练什么"。
2. `live/state.py` 新增 `_focus_competencies(scorecard)`：growth_items 去重保序 → 回退 weak_competencies；`weak_areas_summary` 与 `coach_briefing`（weakest 取 `focus[0]`）都改走它——语音教练焦点与报告同口径。
3. 前端 `components/prep/study-plan.tsx`：空计划卡按语义分流文案——完成且有分数但无短板 → `prep.noGapsTitle/noGapsBody`（新 i18n 键，zh/en 同步）；未出分 → 原有引导。

**兼容**：旧 ScoreCard JSON 缺 `growth_items` → Pydantic/zod 默认 `[]` → 回退链接管，无需数据迁移。

### 5.2 阶段 2 — practice_state 持久化与计划合并（R3）

- 存储：迁移 0007 JSONB 对象 `{competency: MasteryState}`，挂**当前面试行**（决策：每场独立，非跨面试聚合）。
- 合并：`CoachPlanRequest` 增 `session_id: str | None`；端点 `get_practice_state` 后传入 `run_coach_plan(..., practice_state)`；模块状态 = `practice_state.get(comp, 派生状态)`。未知会话 → `None` → 无覆盖，best-effort 不阻塞计划生成。
- 前端：`requestCoachPlan(scorecard, language, sessionId)`；prep 页仅在**真实会话**视图传 `sessionId`（示例预览态传 `undefined`，保持纯分数卡派生）。

### 5.3 阶段 3 — 针对性补题 drill（R2）

- 存储：迁移 0008 JSONB 数组；与 `context.plan.questions` **物理分离**（面试计划是封存评分依据，drill 永不被评分消费——结构性防泄漏，无需评分侧设防）。
- 生成：`coach/prompts.py drill_prompts`（要求 `question_en/question/answer`，语言用 `language_name()` 全称）→ `coach/__init__.run_generate_drills`：MockLLM/失败安全（`_guarded` 返回 None 则空集）、`id=f"drill_{uuid4().hex[:10]}"`、非英文时 `text` 同时携带 `en` 与目标语言。
- 端点：`POST /api/coach/drill` 先查已存（命中即返回，不调 LLM），未命中则从 ScoreCard 取 evidence（能力项 evidence 优先，回退成长条目散文），生成后 `add_drill_items` 落库并返回。
- 前端按需触发：`prep/page.tsx` 计算出"该激活模块在真题卡面无对应条目"（溢出）且处于真实会话视图时才调 `requestCoachDrill`；结果经 `buildStudyCards(..., drills)` 追加为闪卡（`front=text[lang]??text.en`，`back=answer`），加载失败静默降级为无 drill（不炸页面）。

### 5.4 阶段 4 — 教练自评回写闭环（R4）

链路（全部后端，前端零改动）：

1. `live/coach_agent.py`：`wrap_up(competency="", mastery="", note="")` 记录 `self.assessment`；仍mutating 内存字段、不触网（turn 路径零延迟代价）。人设提示（`coach_agent_instructions`）同步要求填自评。
2. `worker_coach.py::_on_shutdown`：`mastery ∈ {unseen,learning,shaky,mastered}` 且 competency 非空才调 `_post_progress`（模块级新函数，复用 `worker.py` 的 `_api_base`/`_internal_headers`，httpx 10s 超时，异常只记日志不阻塞关闭）；兜底收梢路径 assessment 为 None → 自然跳过。
3. `api/coach.py`：`POST /api/coach/progress`（写密钥守护）——`get_practice_state` 判会话存在性（None→404）→ `set_practice_state` 合并。`mastery: MasteryState` 为 Literal，非法值被 FastAPI 422 挡在落库前（**决策：不信任 worker 侧过滤，服务端二次设防**）。
4. 闭环生效：下一次 `POST /api/coach/plan`（带 session_id）读同一 `practice_state`，被教练过的模块显示自评档位。

```
CoachAgent.wrap_up(competency, mastery)
  → worker_coach._on_shutdown → _post_progress
  → HTTP POST /api/coach/progress (X-Internal-Secret)
  → repo.set_practice_state → sessions.practice_state
  → GET plan(带 session_id) → 模块 status=mastered …
```

## 6. 前端要点（apps/web）

- 页面：`/`（落地）、`/setup`（配置）、`/prep`（计划+卡+教练 CTA+回显）、`/interview/[id]`（语音/文字面试）、`/interview/coach`（语音教练房，`?session=` 验真才铸 token，房间名 `coach_<sid>` 与面试房物理隔离）、`/report/[id]`（报告）、`/session/[id]`、`/login`、`/signup`、`/avatars`、`/voice-test`。
- BFF 三把秘密（`LIVEKIT_API_SECRET`/`INTERNAL_API_SECRET`/Supabase 会话）只存在于服务端；`lib/livekit.ts` 首行 `import "server-only"` 构建期防越界；"先验会话、再签令牌、权限最小"顺序不变量。
- 读取纪律：`lib/session-read.ts` `cache: "no-store"` + 超时 + 失败兜底 null（fail-closed）；回退示例数据**不代表**读取失败原因，空结果与调用异常分离处理。
- `lib/prep-filter.ts buildStudyCards`：真题卡（题干→范文/评分要点）+ 本轮扩展的 drill 卡追加段；`lib/api.ts requestCoachPlan/requestCoachDrill` 对非常规响应容错（非数组返回 `[]`）。
- i18n：`lib/i18n/messages/{en,zh}.ts` 双词典，`i18n.test.ts` leafPaths 双向对齐钉死。

## 7. 提示词与语言不变量

`prep/prompts.py language_name()` 是语言码→全称的唯一真源；出题/评分/报告/教练计划/drill 五条管线的输出语言指令全部引用它，禁止裸语言码进提示词（`test_voice_coach`/`test_coach` 有断言）。`LocalizedText` 展示取值统一 `text[lang] ?? text.en ?? 任一值`。

## 8. 关键技术决策与理由

| 决策 | 理由 / 被否方案 |
|---|---|
| 形态 Y（成长条目 1:1 模块，去分数线） | 分数线制造两页口径分裂；被否：仅改文案映射（治标，数据仍分裂） |
| practice_state 挂单场会话 | 与"上一场面试"产品语义一致，零新表；被否：跨面试聚合（需用户档案层与裁决规则，留待有真实数据后设计） |
| 教练自评 = 模型自评+标注非正式 | 复用现有 turn 路径零额外评分成本；被否：加规则复核层（为回路信号付出打分级成本不值） |
| 自评写回走 HTTP 端点 | 内存模式 worker/API 双进程，直写 `deps.repo` 落进没人读的字典（transcript 直写是已知旧局限，不再扩大）；被否：直写 |
| drill 独立列而非并入 plan.questions | 面试计划封存是评分依据；结构性隔离优于评分侧过滤 |
| drill 服务端幂等缓存 | 防重复烧 LLM；卡片"重进不消失"顺带达成 |
| mastery Literal 双设防（worker 过滤 + 端点 422） | 端点同时面向未来其他调用方，不能信任单一客户端 |
| 新列全部 `add column if not exists` + 默认值 | 与 0004 coach_transcript 先例一致，旧行/内存仓零迁移成本 |

## 9. 降级矩阵（本轮路径相关）

| 条件 | 行为 |
|---|---|
| 无 Supabase | 内存字典；重启丢数据；跨进程写回靠 HTTP（已全链路如此设计） |
| 无 LLM Key | MockLLM：list 字段返回 1 个元素——plan/drill 均能出确定性假数据，测试与演示不炸 |
| `INTERNAL_API_SECRET` 未配 | progress 端点开放（与全站写端点同哲学） |
| 旧 ScoreCard 无 growth_items | `_focus_competencies`/`run_coach_plan` 回退 weak_competencies |
| drill 生成失败/为空 | 返回空 items，前端该模块无补充卡，页面不报错 |
| wrap_up 未携带合法自评 | worker 侧丢弃，practice_state 不变 |
| progress POST 失败 | 仅日志告警，会话关闭不受影响 |
