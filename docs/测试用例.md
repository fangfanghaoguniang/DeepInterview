## 0. 测试环境与前置准备

**服务编排**（`pnpm dev` 只起前端，Agent API 必须手动起）：

```bash
# 终端1  根目录
pnpm dev                                   # web → localhost:3000
# 终端2
uv --directory apps/agent run uvicorn deepinterview_agent.app:app --port 8000
# 终端3（仅语音用例需要，需 livekit extra 与 keys）
uv --directory apps/agent run python -m deepinterview_agent.worker start
uv --directory apps/agent run python -m deepinterview_agent.worker_coach start
```

**数据库**：本机 `.env` 未配 Supabase 时走内存仓（重启即失，用例须在同一进程存活期内完成）；配 Supabase 前先应用迁移 `supabase/migrations/0007_practice_state.sql`、`0008_drill_items.sql`。

**通用前置数据**（除特别说明）：完成一场**有答案、已出分**的模拟面试，记下其 session id，报告页可访问 `/report/<id>`，prep 页处于该会话的真实视图（非示例预览）。

## 2. R1 报告↔计划↔教练口径一致（阶段 1）

### TC-R1-01 成长条数 = 计划模块数（核心断言）
- 前置：通用前置数据（确保报告"成长空间"区块显示 N≥2 条）。
- 步骤：记录报告页成长空间条数 N → 打开 prep 页该会话学习计划。
- 预期：学习计划模块数恰为 N，模块 competency 与成长条目一一对应；**不再出现**"报告 3 条、计划 1 个模块"的分数线截断。

### TC-R1-02 模块内容与报告同源
- 步骤：点开任一模块查看 rationale/依据文字。
- 预期：文案来自报告成长条目原文（同语言），不是另行生成的通用建议。

### TC-R1-03 教练焦点与报告一致
- 前置：同一会话进入语音教练（或读 coach worker 日志中的 briefing）。
- 预期：开场简报 "Focus areas … (weakest first)" 的维度集合 = 报告成长空间集合；最弱维度取成长条目首位。

### TC-R1-04 旧数据兼容回退
- 前置：构造/使用一份 growth_items 为空但 weak_competencies 非空的旧 ScoreCard（可直接对旧会话出分）。
- 预期：计划仍按 weak_competencies 出模块；教练简报正常；页面不报"数据缺失"。

### TC-R1-05 空态语义分流
- 前置 A：一场全部能力 ≥ 阈值、无成长条目的出分面试。prep 页预期显示 **"没有需要补强的短板"** 空态卡（zh）/ "No growth areas to work on"（en），而非旧英文兜底文案。
- 前置 B：尚未出分/无会话。预期显示原有"先完成一次面试"引导，两者文案不得互换。
- 语言切换 zh↔en 后两态文案均正确。

## 3. R3 练习掌握度持久化（阶段 2）

### TC-R3-01 计划携带会话级掌握度
- 步骤：不经代码，先用 curl 模拟写回（等价于教练自评）：
  ```bash
  curl -s -X POST localhost:8000/api/coach/progress \
    -H 'Content-Type: application/json' \
    -d '{"session_id":"<sid>","competency":"<报告中的某维度>","mastery":"mastered"}'
  ```
  预期返回 200 且回显三字段 → 刷新 prep 页学习计划。
- 预期：该维度模块状态徽标变为 **mastered**；其余模块仍为分数派生的 shaky/learning。

### TC-R3-02 每场独立
- 步骤：同一 LLM 配置下新开一场面试（新 sid）。
- 预期：新场计划中同维度状态回到分数派生默认值，不受旧场 mastered 影响。

### TC-R3-03 未知会话拒绝
- `curl` 同上但 `session_id` 乱填 → 预期 **404**；`mastery:"expert"` → 预期 **422** 且该会话 practice_state 不变。

### TC-R3-04 示例预览不串态
- 步骤：prep 页无真实会话（示例数据视图）。
- 预期：计划请求不带 session_id，状态纯分数卡派生，与 TC-R3-01 写入互不影响。

## 4. R2 溢出维度针对性补题（阶段 3）

### TC-R2-01 溢出模块出卡
- 前置：让成长条目包含一个面试未考察的维度（形态 Y 下天然会出现：报告点名但无该维度真题的模块）。
- 步骤：prep 页切到该模块的卡面。
- 预期：短暂加载后出现 3 张新练习卡（正面=问题、背面=3-6 句参考答案），语言与面试语言一致。

### TC-R2-02 幂等与缓存
- 步骤：刷新页面再次进入该模块 → 观察 Network 中 `/api/coach/drill` 响应与 agent 日志。
- 预期：卡片**内容不变**（同 id），日志无第二次出题 LLM 调用；换另一维度首次打开则触发生成一次。

### TC-R2-03 不污染评分面（边界防回归）
- 步骤：drill 生成后重新查看报告页与 `/api/session/<sid>` 的 `context.plan.questions`。
- 预期：面试题目集数量与内容零变化；评分/总分/成长条目不变；drill 仅存在于独立 `drill_items`。

### TC-R2-04 失败静默降级
- 前置：MockLLM 或断 LLM Key。
- 预期：drill 请求返回空 items 或失败时，模块卡面维持"无可复用卡片"的既有空态，页面不白屏不弹错。

## 5. R4 语音教练自评闭环（阶段 4）

### TC-R4-01 端到端闭环（本轮主验收）
- 前置：coach worker 已起；某维度在计划中显示 shaky。
- 步骤：prep 页进入语音教练 → 围绕该维度练几轮 → 教练宣布收尾挂断（或说"结束"触发 wrap_up）→ 回 prep 页刷新学习计划。
- 预期：该维度状态变为教练自评档位（通常 learning/mastered）；agent 日志无 progress POST 报错。
- 同时确认：prep 页"上一次教练会话"回显仍正常（轮次+收梢句），自评**不**被包装成分数展示。

### TC-R4-02 兜底收梢不写脏数据
- 步骤：进入教练房后直接关闭页面（无 wrap_up，或触发软轮次上限收梢）。
- 预期：practice_state 不变；关闭流程无异常日志；coach_transcript 照常落库。

### TC-R4-03 非法自评拦截
- 手段：curl 直调 progress 端点送 `mastery:""` / `"good"` → 预期 422；worker 侧代码路径已由 `_VALID_MASTERY` 过滤（离线不可单测，现场以 TC-R4-02 佐证）。

### TC-R4-04 写密钥模式（可选，托管形态）
- 前置：agent 配 `INTERNAL_API_SECRET=xxx` 重启。
- 预期：无头/错头 POST progress → 401；worker（读同一 `.env`）写回仍成功；读端点不受影响。

### TC-R4-05 Supabase 模式持久性（可选）
- 前置：配好 Supabase + 应用迁移 0007/0008。
- 步骤：完成 TC-R4-01 后**重启全部进程**再看该会话计划。
- 预期：掌握度与 drill 卡仍在（JSONB 列持久化验证）。
