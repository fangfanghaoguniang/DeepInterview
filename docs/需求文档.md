# DeepInterview 需求文档

> 版本：v1.1（2026-11）
> 状态：与当前代码库一致（含"报告↔教练口径一致与练习闭环"四阶段改造）
> 对应代码：monorepo 全量；本文描述的是**已实现**能力，非愿景清单

---

## 1. 产品概述

### 1.1 定位

DeepInterview 是一款自托管（self-hosted）的 AI 模拟面试与备考教练产品。用户提交简历与目标岗位 JD 后，系统自动完成：出题 → 模拟面试（语音或文字）→ 逐能力项评分出报告 → 生成个性化学习计划与闪卡 → 提供苏格拉底式语音教练，并以练习掌握度闭环反向更新学习计划。

### 1.2 目标用户

- 准备技术面试的软件工程师（校招到 staff 级，覆盖后端/前端/全栈/移动/数据/SRE/安全/PM 等 32 个内置角色画像，见 `skills/*.md`）；
- 重视隐私、希望数据留在自己环境里的用户（本地优先架构，默认零外部依赖可跑通）；
- 中文/英文/越南文等双语或多语面试场景用户。

### 1.3 核心价值主张

1. **一次闭环**：从"我哪里弱"到"我练了什么、练到什么程度"是同一个数据口径，报告页看到成长空间 = 学习计划模块 = 闪卡练习内容 = 语音教练聚焦维度。
2. **可降级**：没有 Supabase 用内存存储、没有 LLM Key 用 MockLLM、没有 LiveKit 用文字面试——任何一层缺失都不阻塞主流程体验。
3. **成本护栏**：语音面试/教练会话有时长与轮次双上限，杜绝无界烧钱。

## 2. 术语表

| 术语 | 含义 | 代码落点 |
|---|---|---|
| Session | 一场面试的全生命周期记录，一行 `sessions` 表/字典项 | `core/persistence/repository.py` |
| ScoreCard | 面试评分卡（能力项得分、证据、成长空间、范文答案等） | `shared_models.ScoreCard` / `packages/shared/src/score.ts` |
| Growth Item | 报告产出的结构化成长空间条目 `{text, competency}`，是短板口径的**单一真相源** | `ScoreCard.growth_items` |
| weak_competencies | 旧口径：分数线（<3 分）筛出的能力项，仅作兼容回退 | `post/report.py` |
| StudyPlan / StudyModule | 学习计划及其模块，一模块对应一条成长空间 | `coach/__init__.run_coach_plan` |
| MasteryState | 练习侧掌握度：`unseen / learning / shaky / mastered` | `packages/shared/src/coach.ts` |
| MasteryLevel | 面试评分档位：`weak / developing / solid / strong`（与 MasteryState 是两套独立词表） | `shared_models.py` |
| practice_state | 每场面试独立持久化的"能力项 → 掌握度"映射 | 迁移 0007，`sessions.practice_state` |
| Drill Item | 针对"溢出维度"（报告点名但面试没考过）按需生成的带答案练习题 | 迁移 0008，`sessions.drill_items` |
| 溢出模块 | 学习计划中没有对应真题可复用为闪卡的模块 | `apps/web/app/prep/page.tsx` |
| wrap_up | 语音教练的唯一退出工具，携带非正式自评 `{competency, mastery, note}` | `live/coach_agent.py` |

## 3. 总体功能需求（存量能力）

### F1 面试备考准备（prep）

- **F1.1** 用户提交简历 URL/文本 + JD + 公司 + 角色画像（skills 库 32 个）+ 语言设定，系统经 LangGraph 管线产出 `InterviewContext`（题目集：题干/追问/评分细则/目标能力项，多语言 `LocalizedText`）。
- **F1.2** 准备过程有分步进度（`progress`）与告警（`prep_warnings`）可查。
- **F1.3** 出题完成前语音入场须可等待（worker 侧上下文加载带重试）。

### F2 模拟面试（live）

- **F2.1** 语音面试：LiveKit 房间 + STT/LLM/TTS 管线，push-to-talk 手动判停、半双工门控（面试官说话即停录）。
- **F2.2** 文字面试回退：无 LiveKit 配置时可在页面完成问答。
- **F2.3** 逐轮问答按题号入册；面试者挂断/模型漏调 `save_answer` 时，从逐字稿按题号**重建答案**（`reconstruct_answers`，含最少词数门槛防闲聊入册）。
- **F2.4** 会话硬护栏：最大时长、最大轮次、超限说目标语言的收尾句（语言感知，非固定英文）。
- **F2.5** 面试结果跨进程写回 API（worker 与 API 是两进程；内存模式下必须走 HTTP，见 NFR-3）。

### F3 评分与报告（post）

- **F3.1** 逐能力项打分（0-5），分档 `weak(<2) / developing(2-) / solid(3-) / strong(≥4)`，附证据。
- **F3.2** LLM 产出报告叙述（summary、strengths、weaknesses 散文、next_steps、语言流畅度报告）。
- **F3.3** 为弱项生成模范答案（model_answers），供闪卡与教练参考答案使用。
- **F3.4**（本轮新增，见 §4）**结构化成长空间 `growth_items`** 取代分数线成为短板单一真相源。

### F4 学习教练（coach）

- **F4.1** 学习计划：`POST /api/coach/plan` 按 ScoreCard 生成模块列表（标题/理由/预估分钟/掌握度状态）。
- **F4.2** 学习闪卡：复用面试真题 + 弱项范文生成卡组；（本轮新增）溢出模块按需补充 drill 卡片。
- **F4.3** 文字问答教练：`POST /api/coach/chat`，可选知识库（LightRAG sidecar）接地，无 KB 时诚实声明不编造引用。
- **F4.4** 苏格拉底语音教练：独立 coach worker（独立分派名，与面试 worker 互不串线）；教练简报注入薄弱维度 + 至多两道该维度真题的"被问到→强答案"私密参考（严禁朗读）；软轮次上限触发模型自发收梢。
- **F4.5** 教练会话逐字稿落库（`coach_transcript`，独立列）且经窄读面端点回显"上一次教练会话"。

### F5 多语言

- **F5.1** 前端界面 zh/en 双词典编译期对齐（`Localized<Messages>`）。
- **F5.2** 五条 LLM 管线（出题/评分/报告/教练计划/drill）输出语言统一用 `language_name()` 全称（Chinese/Vietnamese/…），跟随面试语言。
- **F5.3** 题目、范文、drill 以 `LocalizedText`（语言码→文本）存储，展示按当前语言取值、缺失回退 `en`。

### F6 知识库（可选）

- **F6.1** `services/lightrag` sidecar 提供 `POST /api/kb/ingest`、`POST /api/kb/query`；主 API 透传供教练接地。

### F7 部署与运维模式

- **F7.1** 零配置本地试用：`pnpm build && pnpm test` 全 mock 可跑；无 Key 时 MockLLM 降级。
- **F7.2** CLI（`cli/`）：init 等命令编排本地部署。
- **F7.3** Docker Compose 与 Vercel 部署路径；Supabase 配置则持久化升级为 Postgres。
- **F7.4** 观测：jsonl trace 黑匣子（一场面试一条主 trace）+ 可选 Langfuse/Sentry。

## 4. 本轮核心需求：报告↔教练口径一致与练习闭环

### 4.0 问题背景

改造前，"弱项"存在两个互不对账的口径：`weak_competencies`（规则按 <3 分筛出）与 `weaknesses`（LLM 散文、无分数门槛）。报告页展示后者文字、学习计划却按前者过滤模块，导致用户在同一产品里看到"报告说我有 3 个成长点，计划只有 1 个模块""教练页聚焦的维度报告上根本没提"这类矛盾。本需求确立**单一真相源**并打通练习闭环，分四个阶段交付（形态 Y：报告列几条成长空间，计划就出几个模块，彻底放弃分数线过滤）。

### R1 结构化成长空间（阶段 1）

- **R1.1** `ScoreCard` 新增 `growth_items: [{text, competency}]`，由报告 LLM 直接产出，`competency` 必须取自本次评分的能力项/考察维度。
- **R1.2** 学习计划一模块对一成长条目：不做分数线过滤；成长条目多于模块上限时按能力分数升序保留（无分数条目排最后，不丢弃语义上最靠前的）。
- **R1.3** 语音教练简报（briefing/weak_areas_summary）改读同一焦点列表。
- **R1.4** 兼容：`growth_items` 为空（旧数据/LLM 未产出）时回退 `weak_competencies`；两者皆空时报告页展示**语义分流的空态**——"面试正常完成但没有短板"与"没有可用成绩"文案区分。
- **验收**：报告页成长空间条数 == 学习计划模块数 == 教练焦点维度集合。

### R2 针对性补题（阶段 3）

- **R2.1** 当学习模块在面试真题中无可复用卡片（溢出维度），前端按需调用 `POST /api/coach/drill`，为该 competency 生成 3 道**新**练习题（题干 + 3-6 句参考答案），存入该场面试的 `drill_items`。
- **R2.2** 幂等：同一会话同一 competency 重复请求返回已存集合，不再触发 LLM。
- **R2.3** 边界：drill 只入学习卡面，**绝不**写入/污染面试计划 `context.plan.questions`（已封存的评分依据）；不计入任何评分。
- **R2.4** 语言：题目与答案按面试语言产出，另存英文对照 `question_en` 作稳定回退键。
- **验收**：溢出模块点开后出现练习卡；刷新页面卡不消失且无第二次生成；面试报告与得分不因 drill 发生任何变化。

### R3 练习掌握度持久化（阶段 2）

- **R3.1** 每场面试行新增 `practice_state`（`{competency: MasteryState}`），**挂当前面试、非跨面试聚合**：新开一场模拟面从零开始。
- **R3.2** 计划端点携带 `session_id` 时，把已存掌握度合并进对应模块 `status`（覆盖分数推导的默认值）；不携带则纯分数卡派生（旧行为不变）。
- **R3.3** 页面重访、服务重启（Supabase 模式）后掌握度仍可见。
- **验收**：某模块被标为 `mastered` 后重进 prep 页仍显示 mastered；另一场新面试同维度不受影响。

### R4 教练自评回写闭环（阶段 4）

- **R4.1** 语音教练调用 `wrap_up` 退出时须携带**非正式自评**：聚焦 competency + mastery（unseen/learning/shaky/mastered 四选一）+ 可选 note。自评定位是"要不要继续练"的回路信号，**不是**评分，UI 与话术不得包装成成绩。
- **R4.2** 教练 worker 在会话关闭时把合法自评经 HTTP `POST /api/coach/progress`（内部写端点，受 `INTERNAL_API_SECRET` 守护）写回 `practice_state`；进程隔离下直写本地 repo 无效，此为强制约束。
- **R4.3** 非法 mastery（含空值）拒绝：端点 422 / worker 侧丢弃，不落库。
- **R4.4** 兜底路径（软轮次上限/硬守卫收梢）无自评时静默跳过，不阻塞关闭。
- **验收**：与教练练完某个维度挂断后，prep 页学习计划中该维度状态即变为教练自评档位。

## 5. 非功能需求

- **NFR-1 本地优先与隐私**：默认数据不出本机；Supabase/Langfuse/Sentry 均为可选接入。
- **NFR-2 可用性分级**：每个外部依赖（LLM Key、Supabase、LiveKit、LightRAG、Kokoro/CosyVoice 语音三件套）缺失时有明确的降级行为，且配置只配一半时启动期大声告警。
- **NFR-3 跨进程一致性**：worker 与 API 双进程；一切需要被 UI 读到的写路径必须经 API（HTTP 传话），禁止依赖进程内共享状态。
- **NFR-4 成本与安全护栏**：语音会话时长/轮次上限；写端点共享密钥鉴权（未配置时 no-op 保证零配置可用）；读端点靠不可猜测的 session id。
- **NFR-5 前后端合同纪律**：TS Zod 为唯一数据合同真相，Python 侧镜像；改合同必须重跑 `gen:schema` 且 parity/roundtrip 测试双向钉死（恰好 32 个注册 schema，子对象内联不注册）。
- **NFR-6 文案完整性**：新 UI 文案必须同时落 zh/en 词典并对齐（leafPaths 双向测试）；占位符 token 保留。

## 6. 明确不做（本轮范围边界）

1. 跨面试的掌握度聚合/学习档案（practice_state 刻意每场独立）。
2. 教练自评的二次校准或规则复核（拍板：模型自评 + 标注非正式即可）。
3. drill 题自动进入下次面试出题池。
4. 对旧 ScoreCard 数据回填 growth_items（用回退链兼容）。
5. 多币种/商业化计费（历史 0002 计费表已被 0006 迁移删除）。
